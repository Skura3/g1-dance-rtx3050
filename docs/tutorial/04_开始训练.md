## 1. 先验证机器人身体和物理环境

```bash
cd "$G1_PROJECT_ROOT"
MUJOCO_GL=egl OPENBLAS_NUM_THREADS=1 envs/training/.venv/bin/python tools/validate_g1.py \
  --mode stand --seconds 10 --output outputs/tutorial_repro/standing
```

应生成 `stand_report.json`、`standing.mp4`。本机历史实测自由基座站立10秒成功，最大倾角约0.336°。这里用的是专门求解平衡并提供LQR/PD反馈的站立控制器，**不是训练出的舞蹈策略，也不是把身体固定在空中**。最初仅给固定PD目标会失稳，因此“默认姿态看起来站着”不等于已经验证物理站立。

接着验证动作能被训练环境读取。若你已经完成第03章，用新参考；若从已准备动作开始，可用 `data/preview/reference_full_contact.npz`：

```bash
MUJOCO_GL=egl OPENBLAS_NUM_THREADS=1 envs/training/.venv/bin/python tools/validate_g1.py \
  --mode play --input outputs/tutorial_repro/reference_full_contact.npz \
  --output outputs/tutorial_repro/gpu_reference_check
```

检查全部616帧、FK一致、无NaN。完成这两步后，才开始策略实验。训练时通常不打开机器人窗口：后台并行仿真更省资源。

## 2. 选择这次实验的名字和参考文件

每次重新尝试用一个新名字，避免覆盖以前成果。下面以 `tutorial_dance_01` 为例。当前电脑如果想先把**训练部分**复刻出来，使用已经检查好的原参考：

```bash
python3 docs/tutorial/scripts/prepare_run.py \
  --name tutorial_dance_01 \
  --motion data/preview/reference_full_contact.npz \
  --batch 32 --use-original-focus
```

如果要使用第03章自己重建的版本，执行下面这一条**代替**上一条，别两条都执行：

```bash
python3 docs/tutorial/scripts/prepare_run.py \
  --name tutorial_dance_01 \
  --motion outputs/tutorial_repro/reference_full_contact.npz \
  --batch 32
```

助手只创建 `outputs/tutorial_runs/tutorial_dance_01/` 中的配置，**不会开始训练**。重复名字会拒绝覆盖。`--use-original-focus` 只接受与原参考内容哈希相同、名称相同的动作，使用原来25%的重点起点；新视频默认关闭旧重点窗口。

生成文件用途：

| 文件 | 用途 |
|---|---|
| session.json | 这次实验名字、参考路径和哈希 |
| finetune.json | 64环境、anchor、微调学习率、batch等 |
| supervision.json | 每4000步评测、每1000步保存等 |
| acceptance.json | 本次验收阈值快照；是工程目标 |
| random_init.json | 另一个随机初始化教学分支，不是微调配置 |

查看你究竟选了哪个动作：

```bash
cat outputs/tutorial_runs/tutorial_dance_01/session.json
cat outputs/tutorial_runs/tutorial_dance_01/finetune.json
```

本章后续命令中明确列出的参考路径示例是已完成的原参考。若选择重建版，请将评测的 `--motions` 同步替换为 `outputs/tutorial_repro/reference_full_contact.npz`。训练本身根据新配置读对应路径。

## 3. 先测预训练模型，不急着训练

```bash
MUJOCO_GL=egl OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
envs/training/.venv/bin/python tools/record_nju_rollout.py \
  --checkpoint data/downloads/nju/e13i_0291000/ckpt_e13i_0291000.pt \
  --motions data/preview/reference_full_contact.npz \
  --output outputs/tutorial_runs/tutorial_dance_01/baseline
```

输出包含物理轨迹 `reference_full_contact_states.npz`、`report.json`、机器人视频和场景文件。它从头跑整段、遇到第一次终止就结束记录，不能中途重置伪装成完整成功。

这是测量“已经在别的动作上训练过的模型，第一次遇到我们的舞蹈会怎样”。即使整段不摔，它也可能转向不准、位置漂移、手臂跟不上。基线的作用是建立可比较的起点，不是作为能否继续训练的精度门槛。

## 4. 为什么先把680维输入扩展成689维

原模型的目标输入包含未来参考姿态/速度等680维，没有显式告诉策略当前机器人相对目标的完整锚点位姿误差。只看局部运动可能出现绝对位置和偏航漂移。上游复现提供 `anchor_obs`，加入9维相对锚点位置/方向信息；我们只做仿真，能获取这类信息。

增加输入会让网络第一层尺寸变化，不能直接把旧权重硬塞进去。工具在指定位置补零列，并同步扩展critic与Adam动量，保留原列顺序和原有知识。新增输入初始影响为零，之后学习如何利用。

```bash
envs/training/.venv/bin/python tools/extend_anchor_checkpoint.py \
  --input data/downloads/nju/e13i_0291000/ckpt_e13i_0291000.pt \
  --output outputs/tutorial_runs/tutorial_dance_01/anchor_initialized.pt
```

应生成旁边的JSON，显示680→689、输出差在数值容差内、优化器形状验证通过。它不会覆盖已存在的输出。**不要对429526或452376这类已经扩展的权重再运行一次。**

这属于利用仿真状态的控制增强。它不等于无需状态估计就能部署到真机，也不是论文原始本体感知输入完全不变的复刻。

## 5. 短测：证明能学习、保存，不判断最终收敛

```bash
MUJOCO_GL=egl OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
envs/training/.venv/bin/python -B tools/finetune_nju.py \
  --config outputs/tutorial_runs/tutorial_dance_01/finetune.json \
  --checkpoint outputs/tutorial_runs/tutorial_dance_01/anchor_initialized.pt \
  --steps 600 --run-name tutorial_dance_01_warmup
```

保持终端打开，等程序自行结束。`-B` 只是不生成Python字节码文件。输出在 `logs/train/tutorial_dance_01_warmup/`；检查 `run_report.json` 的 `ok`、实际步数、`policy_finite` 和最新权重。前64步重新填充缓存，然后更新世界模型、策略与critic。这里第一次换到单舞蹈库，会清空公开大动作库的采样统计。

短测可能因 `max_hours` 上限先结束，因此总是读报告，不假定一定新增600步。重点是：

- 没有CUDA OOM、非法张量、优化器形状或文件路径错误。
- `updates.jsonl` 出现实际wm/policy更新，非有限数检查通过。
- `ckpt_latest.pt` 确实产生，报告指向NJU源码。
- GPU温度/总显存正常，磁盘能写检查点。

策略此时动作变差、偶尔摔倒仍可正常进入长训。短测不是要求达到最终阈值的资格考试。不要每600步换方法、换目标，再把试错归咎于“强化学习不收敛”。

## 6. 长期训练：沿同一条学习历史继续

```bash
MUJOCO_GL=egl OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
envs/training/.venv/bin/python -B tools/finetune_nju.py \
  --config outputs/tutorial_runs/tutorial_dance_01/finetune.json \
  --checkpoint logs/train/tutorial_dance_01_warmup/ckpt_latest.pt \
  --run-name tutorial_dance_01_long \
  --keep-sampler --until-targets \
  --supervision outputs/tutorial_runs/tutorial_dance_01/supervision.json
```

这次**从刚才的最新权重接着训练**，不是重新从公开291000开始。`--keep-sampler` 保留同一动作库的采样统计；`--until-targets` 取消默认600步/小时短预算，改用低频监督评测。每次进程重启仍重建缓存并预热64步。

默认每新增4000迭代评测一次完整动作，周期保存约1000步一次。两次连续不同检查点都通过阈值后，再做种子11、23、37的初态扰动复核；都通过后保存接受版并停止，仍需要人看观感。达不到阈值就继续，**可能长期不自动停止**。用户可随时按第05章安全结束。

这条是前台教学命令。关终端、注销或休眠会影响运行；夜间无人值守请按第07章配置独立服务与看护。不要在前台已经运行时再启动服务，变成两个训练作业。

## 7. 训练时你应该看什么

另开一个普通终端：

```bash
cd "$G1_PROJECT_ROOT"
cat logs/train/tutorial_dance_01_long/status.json
tail -n 5 logs/train/tutorial_dance_01_long/updates.jsonl
tail -n 1 logs/train/tutorial_dance_01_long/evaluations.jsonl
nvidia-smi
```

第一次评测之前 `evaluations.jsonl` 尚不存在是正常的。`status.json` 中 `iteration` 持续增长，`num_updates` 也应增长；`evaluating` 表示暂时停采样去评测，完成后继续，缓存仍保留在父训练进程。若程序在初始化，首次Warp编译可能需要时间。

TensorBoard 可选：

```bash
envs/training/.venv/bin/tensorboard --logdir logs/train/tutorial_dance_01_long --host 127.0.0.1 --port 6006
```

在浏览器打开 `http://127.0.0.1:6006`。看真实仿真回报、世界模型1步/8步预测误差、想象回报、存活率、每步耗时。它们解释学习过程，最终动作判断仍用完整物理评测。

## 8. 本次参数怎样理解

| 参数 | 本次长训/最终设置 | 改它会影响什么 |
|---|---|---|
| num_envs | 64 | 每次采样的并行量，环境/缓存显存 |
| replay_capacity | 每环境512，约32768条转移 | 能保留的近期经验；不是512个视频 |
| batch_size | 初始32，后512，再1024；WM与policy都改 | 每次优化的样本量、梯度噪声、显存与耗时 |
| window | 8 | 世界模型监督预测窗口 |
| horizon | 16 | 策略想象窗口；增大会明显增加激活显存 |
| history / future_frames | 10 / 10 | 过去观测与未来参考的上下文 |
| updates_per_env_step | 0.4 | 采样迭代与优化周期比例 |
| batches_per_update | 2 | 每个世界模型优化周期的批次数 |
| lr_constant | 2e-5 | 实际微调学习率；不能只看配置里基础lr=2e-4 |
| action_noise_std | 0.05 | 执行侧探索噪声，帮助模型覆盖动作变化 |
| obs_noise / reset_noise | true / true | 训练观测与初态扰动 |
| domain_randomization | false | 未做真机物理参数随机化 |
| tilt_hinge_weight / knee | -24 / 0.17rad | 对相对参考倾斜误差超阈值增加惩罚 |
| anchor_obs | true | 仿真位置/朝向反馈；改变输入维度 |
| fail_reset_frac | 原片0.25 | 更多从已知质量问题之前的窗口开始 |
| compile | null | 避免编译/图缓存的额外负担 |

最终保留完整预训练网络结构，没有把大权重塞进早期小网络配置。`g1_3050_tuned.json` 等是早期随机小网络性能探索，不能用来替代NJU微调配置。

### 何时可以扩大batch

先让32稳定执行，再测512/1024。关闭动态壁纸请使用程序正常退出方式；不要误杀桌面显示服务。看 `nvidia-smi` 的**总显存**，不是只看torch峰值。评测子进程、MuJoCo/Warp、桌面也要显存，不能占到4096MiB边缘才算充分利用。

扩大batch**不自动要求**同比扩大环境数、学习率、回放缓存或时域。学习率线性放大不是本实验已证明的规则。我们保留2e-5、64环境、H16和UTD0.4，扩大批量后观察2–3个完整评测点，再判断质量与单位时间进步。更大batch减少噪声却也可能慢下来或降低多样性；GPU利用率高不等于学习最快。

如果需要从32改到512，先按第05章请求安全保存退出，然后复制本次配置，在新配置里只修改 `wm_trainer.batch_size`、`policy_trainer.batch_size` 为512；从最新权重启动新的run-name并加 `--keep-sampler`。JSON运行时已经读入，修改磁盘文件不会自动更新活着的训练进程。

## 9. 真正的“随机权重从零训练”分支

这条用于理解学习过程，**与前面的成功路线不同**。不加载公开权重，也不继承291000步。我们尚未证明它在3050上能达到这段舞蹈同等观感。不要与长期微调同时运行。

准备配置的脚本已生成 `random_init.json`：16环境、小网络、batch32、H16，20,000步/1小时预算。预算是防止初学者失控运行，不是收敛时间承诺。

```bash
G1_SUPERMIMIC_SOURCE=original MUJOCO_GL=egl OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
envs/training/.venv/bin/python tools/train_3050.py \
  --config outputs/tutorial_runs/tutorial_dance_01/random_init.json \
  --threads 1 --fast-fk --smoke
```

80步仅检查随机网络能采样、更新和保存。真正启动新的随机初始化预算训练：

```bash
G1_SUPERMIMIC_SOURCE=original MUJOCO_GL=egl OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
envs/training/.venv/bin/python tools/train_3050.py \
  --config outputs/tutorial_runs/tutorial_dance_01/random_init.json \
  --threads 1 --fast-fk
```

不加 `--resume` 就重新随机初始化；加 `--resume 检查点路径` 才是续训，网络形状必须匹配。这里使用CuboiLeo入口，**没有本地NJU长期监督器的自动评测/STOP文件机制**。预算结束会存盘，提前中断不保证保存最后内存状态。再次续训前要将配置的总迭代上限设为大于checkpoint计数、使用新run_name，避免旧预算直接结束。

随机分支应使用 `tools/evaluate_nju.py` 的基础benchmark或按对应上游评测接口，先关注完成率和回报；不要假定专为固定原片写的比较播放器能接受任何参考长度。若长期学习困难，可以先选简单站立/摆臂片段作为独立课程实验，但要明确换了任务，不能把简单片段完成当成原舞蹈成功。

**建议你第一次独立复刻走预训练微调主线**：先学会完整工程流程、判断评测和保存，再做随机初始化实验，会更容易区分算法学习困难和环境搭建错误。
