# 02 电脑、环境、源码和下载

> **GitHub读者先看 [公开版复刻入口](../PUBLIC_REPRODUCTION.md)**：设置G1_PROJECT_ROOT、恢复上游源码、下载Release。原机/home/djs/supermimic、历史outputs/logs和systemd实例未原样分发；已有成果的播放/续训请使用公开版入口的命令。


[目录](README.md) · 上一章：[理解方法](01_从零理解与论文.md) · 下一章：[处理视频](03_视频到机器人动作.md)

## 1. 你的电脑能做什么

本次实测机器：RTX 3050 Laptop 4096MiB、i5-11400H、约 15GiB 内存、Linux、NVIDIA 驱动 535.309.01。它已经完成这段视频的重建、重定向和单舞蹈预训练微调。4GB 不是完全不能做；关键是将视觉处理和训练分开运行、控制批量、复用预训练能力。

它不等同论文的一张 H100；大动作库从随机初始化、长视频高分辨率同时处理、多进程一边训练一边渲染，都可能超出合理资源范围。最终训练采用 64 并行环境、batch1024；这是逐步测量后的设置，不是刚安装好就应强行填满显存。

本教程编写时根分区只剩约 **6GiB**。现有环境还能检查，但要重装环境、重新解压源码或创建许多检查点前，应先在其他磁盘准备空间。新机器建议准备至少几十 GiB，若要保存多个环境、权重和日志，预留 40–60GiB 更从容；这是容量规划建议，不是硬性最低值。不要为了腾空间删除最终归档。

## 2. 终端最小入门

打开终端，一次复制一块命令：

```bash
cd "$G1_PROJECT_ROOT"
pwd
ls
nvidia-smi
df -h .
```

- `cd`：进入目录。`pwd` 应显示 `/home/djs/supermimic`。
- `ls`：列出目录里的文件。应能看到 `tools`、`configs`、`third_party`、`reference_video.mp4`。
- `nvidia-smi`：查看显卡、显存、温度、占用进程。窗口中的 CUDA Version 是驱动能力提示，不是当前 Python 所用 PyTorch 的版本。
- `df -h .`：查看当前磁盘剩余容量。
- `Ctrl+C`：请求当前前台程序中断。训练应优先使用第 05 章的保存退出步骤。
- 多行命令末尾的 `` 表示下一行仍属于同一命令，后面不要再加空格。
- `.venv-motion/bin/python` 指定一个具体 Python；`envs/training/.venv/bin/python` 是另一个。不要随手改成 `python`。

本教程不要求 conda。直接使用环境内解释器，能减少“激活了错误环境”的问题。若你在 ROS 终端里操作，请新开普通终端，或在当前终端执行 `unset PYTHONPATH`，避免 ROS 包覆盖本项目依赖。

## 3. 目录是做什么的

```text
supermimic/
  reference_video.mp4       原视频，不覆盖
  .venv-motion/             Python3.10：视觉重建、重定向、参考修正
  envs/training/.venv/      Python3.12：mjlab、SuperMimic、策略评测
  third_party/             固定版本的第三方源码，含本地补丁
  data/downloads/          原始下载文件、训练 wheel、NJU 权重
  data/video/              转码视频
  data/motions/            GMR 中间 PKL
  data/preview/            待检查或明确指定使用的 NPZ
  tools/                  我们写的入口脚本
  configs/                JSON 配置、接触标注、版本记录
  outputs/                重建输出、评测、归档
  logs/train/             每个独立训练作业的检查点与日志
  docs/tutorial/          这份教程
```

`preview` 只是目录名称。最终训练明确读取其中 `reference_full_contact.npz` 一个文件；不能因为名字叫预览就认定它没有参与训练，也不要让程序扫描一整个含坏候选的目录。

## 4. 当前电脑：先检查，通常不用重装

```bash
cd "$G1_PROJECT_ROOT"
.venv-motion/bin/python -V
envs/training/.venv/bin/python -V
.venv-motion/bin/python tools/check_ready.py
envs/training/.venv/bin/python tools/check_training.py
```

前两个应分别为 Python3.10 和 3.12。本机训练解释器为 3.12.16。`check_ready.py` 检查模块和模型文件，并写 `outputs/readiness.json`；文件存在检查不等于重新验证全部内容。`check_training.py` 会做 Torch/Warp GPU 基础检查并更新 readiness 报告；它不启动训练，也不证明训练收敛。

核对下载文件实际内容：

```bash
.venv-motion/bin/python tools/audit_downloads.py
```

这个工具在CPU上逐个检查约定位置的7项文件（5个视觉/人体模型和2个wheel），检查哈希/格式/兼容性并写报告；它不下载、不替你搬运缺失文件，任何项失败会返回非零退出码。NJU权重另外按后文哈希和实际加载验证。此前所有必要素材已核对完成，历史结果在 `outputs/download_audit/`。

## 5. 为什么有两个环境

| 内容 | 运动处理环境 | 训练环境 |
|---|---|---|
| Python | 3.10.12 | 3.12.16 |
| PyTorch | 2.5.1+cu121 | 2.14.1+cu126 |
| NumPy | 1.26.4 | 2.5.4 |
| MuJoCo | 3.3.7 | 3.16.0 |
| 主要额外包 | SMPL-X、Mink、GVHMR、PyTorch3D transforms | mjlab1.6.0、mujoco-warp3.16.0、warp-lang1.18.0+cu12 |

这些是本机已安装版本快照，不是宣称当前互联网最新版本。依赖隔离是因为视觉项目与训练项目所需 Python/Torch 组合不同。把所有包装进一个环境，容易为满足其中一个项目而破坏另一个。完整清单：[版本说明](environment/README.md)。

## 6. 换新电脑，先取得“本项目工具”

本仓库已公开包含定制tools、configs、envs/training和教程。克隆本仓库即可获得它们，再运行 `python3 tools/bootstrap_sources.py` 恢复固定上游源码及补丁。只克隆NJU或GVHMR仓库不会获得这些集成工具。

在仓库根目录设置 `export G1_PROJECT_ROOT="$(pwd)"`。不要复制虚拟环境到不同电脑后假定能用；它可能包含绝对路径与外部依赖，新电脑应重新创建。

本机 `.venv-motion/pyvenv.cfg` 的 `include-system-site-packages=true`，历史上复用了系统可工作的 Torch。因此只复制这个环境可能漏掉系统包。下面给出独立环境的安装方式，**没有在本次写教程时删除现有环境做联网洁净重装验证**。

### 如果第三方源码没复制齐

源码记录在 [`configs/upstream_sources.json`](../../configs/upstream_sources.json)，应使用以下固定提交，不能直接以未来的 `main` 代替。

| 目录名（位于 third_party） | 仓库 | 固定提交 |
|---|---|---|
| GVHMR | https://github.com/zju3dv/GVHMR | ee960bb6e2ea2d381aa97f08e9b71ef320b624b1 |
| GMR | https://github.com/YanjieZe/GMR | 25f56db79ac411258b377b6d4ccba0c8ff3372ac |
| SuperMimic-Reproduced | https://github.com/CuboiLeo/SuperMimic-Reproduced | ba6105349069bf040f1fdad60873d13138d505a2 |
| mjlab | https://github.com/mujocolab/mjlab | 8bb2bc9e187797689ec82c78c35019afd2fd0376 |
| SuperMimic-Repro-Sim2Real | https://github.com/NJU-R-L-Group-Embodied-Lab/SuperMimic-Repro-Sim2Real | f8f60d7bbdba68468c050ef100af02d752ca238e |
| pytorch3d | https://github.com/facebookresearch/pytorch3d | 本机0.7.9源码；保留现有副本，归档 SHA 见来源 JSON |

例如仅当 `third_party/GVHMR` 不存在时：

```bash
git clone https://github.com/zju3dv/GVHMR third_party/GVHMR
git -C third_party/GVHMR checkout ee960bb6e2ea2d381aa97f08e9b71ef320b624b1
```

其他仓库按表替换地址、目录名和提交。下载两次仍失败就停止，使用浏览器下载对应 commit 的 ZIP/TAR；解压后去掉多余外层目录。正确位置如 `third_party/GVHMR/hmr4d/`，不是 `third_party/GVHMR/GVHMR-main/hmr4d/`。这些包不是整个 Git 历史，不要在无 `.git` 的 ZIP 目录运行 checkout。

若复制了已打补丁源码，不要重复 `git checkout` 抹掉补丁。若从干净源码恢复，先运行本地 `tools/patch_gvhmr_lowmem.py`；完整补丁记录见 `configs/upstream_changes.patch`。训练原仓库 pyproject 的本地 mjlab、Torch/Warp wheel 路径和训练循环补丁也要保留；第 06 章解释。公开版优先使用bootstrap_sources.py，它执行固定版本恢复、补丁和SHA256验证；下载失败后再手动处理。

## 7. 模型文件下载位置

### 人体模型和视觉权重

- SMPL-X 官方站：https://smpl-x.is.tue.mpg.de/ 。需要自己注册、同意许可，下载含 **SMPLX_NEUTRAL.npz** 的 SMPL-X 模型。SMPL、男/女单独模型或 AMASS 动作数据不能替代这里的 neutral NPZ。
- GVHMR 官方安装说明：https://github.com/zju3dv/GVHMR/blob/main/docs/INSTALL.md 。
- 四个视觉权重的官方说明所列目录：https://drive.google.com/drive/folders/1eebJ13FUEXrKBawHpJroW0sNSxLjh9xD?usp=drive_link 。

最终放成这样：

```text
third_party/GVHMR/inputs/checkpoints/
  body_models/smplx/SMPLX_NEUTRAL.npz
  yolo/yolov8x.pt
  vitpose/vitpose-h-multi-coco.pth
  hmr2/epoch=10-step=25000.ckpt
  gvhmr/gvhmr_siga24_release.ckpt
```

本机 ViTPose 实际文件为带 `-001` 的名字，通过软链接提供脚本所需名称。新机器可以直接放正确完整权重为 `vitpose-h-multi-coco.pth`；不是随便把不同模型改同名。`.npz/.pth/.pt/.ckpt/.whl` 保持原文件，别把它们当普通压缩包展开成文件夹；外层 `.zip/.tar.gz` 才需要解压。`.partial` 文件不能当完整下载。

这条轻量路线使用 SimpleVO，不安装 DPVO，也不需要下载整套 AMASS、BONES-SEED 或训练 GVHMR 的数据集。

### 训练环境的两个 wheel

放在 `data/downloads/wheels/`：

1. `torch-2.14.1+cu126-cp312-cp312-manylinux_2_28_x86_64.whl`
   下载：https://download-r2.pytorch.org/whl/cu126/torch-2.14.1%2Bcu126-cp312-cp312-manylinux_2_28_x86_64.whl
   SHA256：`75727245346d8f92224a860bf40c56bd681edcfa0456d01d7dfcb0bf6f0cf86c`
2. `warp_lang-1.18.0+cu12-py3-none-manylinux_2_28_x86_64.whl`
   下载：https://github.com/NVIDIA/warp/releases/download/v1.18.0/warp_lang-1.18.0%2Bcu12-py3-none-manylinux_2_28_x86_64.whl
   SHA256：`6dda3c163dde4edaa7d46ade9fff3ddb1126ee7b147d9d890cd38cc70dafd656`

核对：

```bash
sha256sum data/downloads/wheels/torch-2.14.1+cu126-cp312-cp312-manylinux_2_28_x86_64.whl
sha256sum data/downloads/wheels/warp_lang-1.18.0+cu12-py3-none-manylinux_2_28_x86_64.whl
```

`cp312` 表示 Python3.12；`x86_64` 表示本机这类 64 位 PC；`manylinux_2_28` 需要相应 Linux 运行库；`+cu12` 很重要。本机普通 Warp1.18 的 CUDA13 运行时曾不兼容旧驱动，换成 CUDA12 wheel 后实际 GPU 编译和执行通过。不要因为文件前半段同名就替换。

驱动535下 CUDA Graphs 被框架禁用；能运行不等于每个新 CUDA 特性都可用。教程不要求更换驱动、超频或解除温控。

### NJU 预训练模型

下载：https://github.com/NJU-R-L-Group-Embodied-Lab/SuperMimic-Repro-Sim2Real/releases/download/v1.0/e13i_0291000.tar.gz

存为 `data/downloads/nju/e13i_0291000.tar.gz`，SHA256：`2aa3f4ca81d7a2e4cdf357d9a3b60d6809fd7d87e0db3005cad55d3ef22709fa`。

```bash
mkdir -p data/downloads/nju
tar -tzf data/downloads/nju/e13i_0291000.tar.gz | head
tar -xzf data/downloads/nju/e13i_0291000.tar.gz -C data/downloads/nju
ls -lh data/downloads/nju/e13i_0291000/ckpt_e13i_0291000.pt
```

只在尚未解压时执行提取。预训练计数291000、原目标输入680维。无需实机 SDK、实机网络配置、部署权重 e24 或物理 G1。只加载你从可信来源取得的 Torch/pickle 文件。

## 8. 新机器安装运动处理环境

以下仅适用于**不存在 `.venv-motion` 的新副本**。当前电脑不要重新执行创建/安装来覆盖工作环境。Linux 发行版不同，系统包名称可能需调整。以具有 Python3.10 的 Ubuntu 为例：

```bash
sudo apt update
sudo apt install -y python3.10-venv python3.10-dev build-essential git ffmpeg libgl1 libegl1
python3.10 -m venv .venv-motion
.venv-motion/bin/python -m pip install --upgrade pip setuptools wheel
.venv-motion/bin/python -m pip install --retries 1 --timeout 25 torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cu121
.venv-motion/bin/python -m pip install --retries 1 --timeout 25 -r docs/tutorial/environment/motion_install_requirements.txt
PYTORCH3D_NO_EXTENSION=1 .venv-motion/bin/python -m pip install --no-build-isolation --no-deps ./third_party/pytorch3d
.venv-motion/bin/python -m pip install --no-deps -e third_party/GMR
.venv-motion/bin/python tools/patch_gvhmr_lowmem.py
.venv-motion/bin/python tools/check_ready.py
```

这里的 requirement 是从当前已安装本地包和必需系统包整理的**建议安装清单，不是经过洁净重装验证的锁文件**。本次没有重新联网下载来证明这些旧版本永远可获取。若依赖冲突，先记录报错和版本，不要执行无差别 `pip install -U`。GVHMR 通过 `tools/common.py` 加到 Python 路径，不必执行它会改变 Torch 版本的原版整套安装命令。

PyTorch3D 只使用纯 Torch 的坐标变换函数。`PYTORCH3D_NO_EXTENSION=1` 不构建 C++/CUDA 扩展，**不支持所有上游 KNN 和渲染功能**；本项目入口经过裁剪避开了它们。照抄上游通用 demo 仍可能失败。

单个资源尝试两次仍下载不了，就保留文件名、来源网址、错误日志，改用浏览器下载。上面 `--retries 1` 限制了请求自动重试，但不要反复重跑整条安装命令。浏览器下载的 wheel 放 `data/downloads/wheels/` 后用对应环境的 `python -m pip install 文件路径` 安装，不要混入不同 Python 或平台的包。

## 9. 安装训练环境

先确认两个 wheel、修改过的源码、`envs/training/pyproject.toml` 和 `uv.lock` 已齐。再运行：

```bash
bash tools/setup_training.sh
envs/training/.venv/bin/python tools/check_training.py
```

安装器用运动环境中的 `uv`，在 `.runtime/python` 安装所需 Python3.12，在 `envs/training/.venv` 建环境，缓存位于 `.runtime/uv-cache`。大 Torch/Warp 采用本地 wheel，其他依赖仍可能联网。

只有所有其他依赖都已经缓存时，才使用 `bash tools/setup_training.sh --offline`。新电脑仅有两个 wheel 不足以离线安装全部依赖。

安装项目元数据默认指向 CuboiLeo 的包；实际 NJU 微调入口会设置 `G1_SUPERMIMIC_SOURCE=nju` 并在 Python 路径前加入 NJU 源码。应看训练 `run_report.json` 的 `source_module`，确认实际加载 `third_party/SuperMimic-Repro-Sim2Real/src/supermimic/...`。不能只看 `pip show supermimic` 就认定正在运行哪个仓库。
