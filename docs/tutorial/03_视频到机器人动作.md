# 03 视频 → 三维人体 → G1 参考动作

> **GitHub读者先看 [公开版复刻入口](../PUBLIC_REPRODUCTION.md)**：设置G1_PROJECT_ROOT、恢复上游源码、下载Release。原机/home/djs/supermimic、历史outputs/logs和systemd实例未原样分发；已有成果的播放/续训请使用公开版入口的命令。


[目录](README.md) · 上一章：[环境](02_环境与下载.md) · 下一章：[训练](04_开始训练.md)

本章先重做你这段视频。所有新产物放入 `outputs/tutorial_repro/`，保护旧动作与最终成果。这里运行的是视觉推理/数值优化，不是在训练机器人策略。建议停止其他 GPU 重任务后逐步执行。

## 1. 检查和转码视频

```bash
cd "$G1_PROJECT_ROOT"
mkdir -p outputs/tutorial_repro
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height,avg_frame_rate,nb_frames,duration -of default=noprint_wrappers=1 reference_video.mp4
.venv-motion/bin/python tools/prepare_video.py --input reference_video.mp4 --output outputs/tutorial_repro/reference_full.mp4
```

本例应是 720×1280、30FPS、370 帧、约12.33秒。工具保留输入视频，生成适合后续读取的 H.264 视频，并记录来源。转码不等于生成更多真实运动信息。换片时优先选择一个人、全身可见、脚和地面可辨、没有切镜头的视频；遮挡、快动作和镜头转动都会增加不确定性。

新机器首次可先做 5 秒小样，检验流程而非判断最终动作质量：

```bash
.venv-motion/bin/python tools/prepare_video.py --input reference_video.mp4 --output outputs/tutorial_repro/reference_pilot.mp4 --duration 5
```

先看转码视频是否正常，没有旋转方向错、黑屏、掉帧或把人物裁掉。视频长宽不是机器人动作维度，不需要把竖屏强行拉伸成横屏。音频不参与本次训练。

## 2. GVHMR：从图像恢复人体运动

```bash
.venv-motion/bin/python tools/patch_gvhmr_lowmem.py
.venv-motion/bin/python tools/run_gvhmr.py \
  --video outputs/tutorial_repro/reference_full.mp4 \
  --output outputs/tutorial_repro/gvhmr/reference_full \
  --preproc-device cuda --preproc-precision fp16 \
  --batch-size 1 --threads 3
```

按五个阶段依次执行，各阶段单独进程退出后释放 GPU 模型：

| 阶段 | 用途 | 主要输出（位于上面的 output 目录） |
|---|---|---|
| track | YOLO 找到并跟踪主角 | preprocess/bbx.pt |
| pose | ViTPose 提取二维人体关键点 | preprocess/vitpose.pt |
| features | HMR2 提取视觉人体特征 | preprocess/vit_features.pt |
| camera | SimpleVO 估计相机运动 | preprocess/slam_results.pt |
| predict | GVHMR 时间模型推断三维人体与世界运动 | hmr4d_results.pt |

缓存命中会显示 `Cached`。相同输入和设置可续跑，不必每次重新提取。如果想证明重新执行过，应使用新的 output 目录。**改了视频、设备或精度，不能直接混用旧缓存**；本地脚本会检查来源，碰到拒绝信息应开新输出目录，不要删除 provenance 文件强行绕过。

`--static-camera` 只有确认固定机位才使用。默认 SimpleVO 估计镜头运动。没有相机标定、单目遮挡、人体比例差异都可能造成尺度/深度/地面误差；输出三维坐标不是测量真值。

显存不足的替代：使用**另一新目录**，把预处理改成 CPU + FP32：

```bash
.venv-motion/bin/python tools/run_gvhmr.py \
  --video outputs/tutorial_repro/reference_full.mp4 \
  --output outputs/tutorial_repro/gvhmr_cpu/reference_full \
  --preproc-device cpu --preproc-precision fp32 --batch-size 1 --threads 3
```

CPU 方案通常更慢；`predict` 阶段仍使用 GPU。下一步的输入路径也要随之改成 `gvhmr_cpu`，不要误用另一个版本。不要同时运行两套重建或训练。

检查重建：

```bash
.venv-motion/bin/python tools/audit_reconstruction.py \
  --reconstruction outputs/tutorial_repro/gvhmr/reference_full/hmr4d_results.pt \
  --video outputs/tutorial_repro/reference_full.mp4 \
  --output outputs/tutorial_repro/reconstruction_audit
```

应覆盖全部370帧，数值有限，并检查关键点与实际人物是否对上。人数多时，自动选出的轨迹可能不是你要模仿的人。视觉错误首先回到这一层解决，不要指望延长机器人训练恢复被识别错的动作。

## 3. GMR：把人体变成机器人

```bash
.venv-motion/bin/python tools/retarget_g1.py \
  --input outputs/tutorial_repro/gvhmr/reference_full/hmr4d_results.pt \
  --output outputs/tutorial_repro/reference_full_gmr.pkl
```

SMPL-X 根据人体参数生成三维身体；GMR 用骨架对应、比例缩放和逆运动学（IK）寻找 G1 各关节角。IK 可以理解成“给定手、脚、身体应该到的位置，倒过来求关节该怎样弯”。正运动学（FK）则是“知道每个关节角，计算手脚在哪里”。

这里不控制机器人与地面的实际受力，只产生姿态。输出 PKL 含 `root_pos`、`root_rot`、`dof_pos`、fps、joint_names 和四元数顺序元数据。四元数是三维旋转的表示，不是四个角度；GMR 的 `xyzw` 在导出时显式转换成下游 `wxyz`，不能手动交换后又被工具交换一遍。

本地工具将 SMPL-X 放在 CPU 分批处理（默认16），逐帧做 IK，修过人体形状/表情批维度不一致的问题。保留370帧和时间，没有为了好看删掉困难片段。

## 4. 导出机器人训练格式

先不对齐地面，做原始预览：

```bash
.venv-motion/bin/python tools/convert_motion.py \
  --input outputs/tutorial_repro/reference_full_gmr.pkl \
  --output outputs/tutorial_repro/reference_full_unaligned.npz \
  --fps 50 --ground-offset 0
.venv-motion/bin/python tools/view_g1.py --input outputs/tutorial_repro/reference_full_unaligned.npz
```

窗口里机器人此时是逐帧摆姿态。关闭窗口后，回到终端继续。不能用这一窗口判断站稳能力。

对**这段原视频**，已人工检查0.9–1.2秒确实有脚支撑，可以用这个区间估计一个固定高度偏移：

```bash
.venv-motion/bin/python tools/convert_motion.py \
  --input outputs/tutorial_repro/reference_full_gmr.pkl \
  --output outputs/tutorial_repro/reference_full_aligned.npz \
  --fps 50 --support-range 0.9 1.2
.venv-motion/bin/python tools/audit_motion.py \
  --input outputs/tutorial_repro/reference_full_aligned.npz \
  --output outputs/tutorial_repro/raw_audit
```

不要默认第一帧一定踩地，也不要对每一帧都把最低脚底压到0；后者会把跳跃变成贴地滑行。固定偏移仅解决整体地面零点，不能解决时间变化的根高度漂移。

NPZ 是一组命名数组的压缩/打包容器。关键字段：

| 字段 | 本例形状或意义 |
|---|---|
| fps | [50]，每秒50个参考采样 |
| joint_pos / joint_vel | [616,29]，弧度 / 弧度每秒 |
| body_pos_w | [616,身体数,3]，世界坐标米 |
| body_quat_w | [616,身体数,4]，wxyz旋转 |
| body_lin_vel_w / body_ang_vel_w | 世界坐标线速度/角速度 |
| joint_names / body_names | 显式名称与排序 |

只把数组改名为NPZ不是有效转换。机器人模型、身体顺序、关节顺序、单位和四元数顺序必须一致。工具会通过同一 G1 模型计算身体位置和速度。

370帧视频的最后一个采样时刻是369/30=12.30秒，容器播放时长约12.333秒。50Hz参考采样到12.30秒，共616帧；评测616个控制步约12.32秒。这个微小差别来自时间采样定义，不是把视频慢放或丢掉大片动作。

## 5. 修复参考：先看问题再修改

看 `raw_audit` 中的报告，重点检查穿地、自碰撞、明显关节超限、支撑脚滑动、根高度漂移、肩膀突然翻转。速度/加速度尖峰是复查线索，不是自动宣判动作不能学的证明。

本次为原视频写了两类人工标注：

- `configs/reference_full_support.json`：源视频的着地帧（30FPS）以及两个肩部异常转换窗口。程序转换成50Hz时刻，做稀疏高度修正与局部平滑。
- `configs/reference_full_contacts.json`：7.8秒附近左右手撑地、左脚支撑的时间区间，并配合GVHMR脚静止置信度与二维脚踝置信度。

先生成新的修复候选：

```bash
OPENBLAS_NUM_THREADS=3 OMP_NUM_THREADS=3 .venv-motion/bin/python tools/repair_motion.py \
  --input outputs/tutorial_repro/reference_full_aligned.npz \
  --output-motion outputs/tutorial_repro/reference_full_repaired.npz \
  --annotations configs/reference_full_support.json \
  --report-dir outputs/tutorial_repro/repair
```

接触修正工具历史上固定读取 `outputs/gvhmr/reference_full` 的人体预测和关键点。因此若要让本次**独立重建**的接触修正读取新目录，先创建专用脚本副本，原工具不变：

```bash
python3 - <<'PY'
from pathlib import Path
src = Path('tools/refine_contacts.py')
dst = Path('tools/refine_contacts_tutorial.py')
if dst.exists():
    raise SystemExit('副本已存在；核对内容后使用，不重复覆盖')
text = src.read_text()
old = "ROOT/'outputs/gvhmr/reference_full'"
new = "ROOT/'outputs/tutorial_repro/gvhmr/reference_full'"
assert text.count(old) == 1, '原脚本已改变，请人工核对读取目录'
dst.write_text(text.replace(old, new))
PY
.venv-motion/bin/python tools/refine_contacts_tutorial.py \
  --input outputs/tutorial_repro/reference_full_repaired.npz \
  --output-motion outputs/tutorial_repro/reference_full_contact.npz \
  --config configs/reference_full_contacts.json \
  --report-dir outputs/tutorial_repro/contact
.venv-motion/bin/python tools/audit_motion.py \
  --input outputs/tutorial_repro/reference_full_contact.npz \
  --output outputs/tutorial_repro/contact_audit
.venv-motion/bin/python tools/view_g1.py --input outputs/tutorial_repro/reference_full_contact.npz
```

此副本只把硬编码读取目录改为新目录，算法不变；CPU重建分支请把 `new` 改为它的路径。这是当前工具的实际限制，不是一个已有的 `--prediction-dir` 参数。

接触修正联合调整根位置与关节，使指定时间手/脚更贴地、支撑点更少滑动，同时保留时间平滑和关节限位。它会改变原动作，历史上单关节最大改动约0.669rad，根位置最大改动约18.9cm；这说明“更适合机器人接触”和“逐像素忠实视频”存在取舍。

本例历史报告中手部支撑高度误差降到毫米级，固定足接触区间的平均水平速度从约0.188降到0.024m/s。它只是特定接触区间的比较，不是整段所有帧都完全没有滑脚，更不是物理可执行性证明。详见 [接触记录](../CONTACT_AND_PERFORMANCE.md)。

## 6. 进入训练前检查什么

```bash
MUJOCO_GL=egl OPENBLAS_NUM_THREADS=1 envs/training/.venv/bin/python tools/validate_g1.py \
  --mode play --input outputs/tutorial_repro/reference_full_contact.npz \
  --output outputs/tutorial_repro/gpu_reference_check
```

这一步让训练环境读取动作并在GPU模型中逐帧核对FK。应全部帧成功、无非有限数、关节与身体排序一致。然后观看全片，特别是7.6–9.3秒的手撑、倒身和高踢腿段。

通过这些检查后，可以进行预训练策略物理评测与微调。**不要求简单PD先能完整跟踪，也不要求瞬时逆动力学筛查100%通过。** 反过来，严重重建错误也不能全部交给RL补救。选择可辨认、结构有效、没有明显致命错误的参考，然后用完整物理评测判断学习表现。

## 7. 如果换一段新的舞蹈

不要只替换 `reference_video.mp4` 后沿用所有缓存和人工标注。建议给新片独立目录，例如 `outputs/my_dance/`，按同样步骤输出。必须重新确认以下内容：

1. 视频FPS、帧数、人物和镜头；输入路径和GVHMR输出目录都换新。
2. GMR输出与NPZ输出换新。先 `--ground-offset 0` 观看，再人工找真实支撑区间。
3. 重新写 `support_frames`。它是**源视频帧号**，例如30FPS的2.0秒约第60帧；不是50Hz参考帧号。没有肩部跳变就把 `shoulder_transition_windows_s` 设为空数组，别照抄旧片8.58秒等窗口。
4. 新建contacts JSON，重新标注手/脚接触的 `start/end` 秒数。不要把腾空标成支撑。原自动阈值0.85/0.6只是启发式，可以保守使用并逐帧复查。若某个手工区间在视频之外，删除或改正，否则脚本会失败。
5. 按上面方法另存接触修正脚本副本，把读取目录改成新GVHMR输出；JSON里的 `source_video` 是说明字段，**改它本身不会改变硬编码读取位置**。
6. `repair_motion.py` 的高度优化主要针对本片漂高的情况，约束偏向下移。新片如果原始脚已深穿地，应先重新估计固定地面对齐，再检查该修复策略是否合适；不要机械套用。
7. 新训练配置明确只读新NPZ。不要保留原片 `fail_reset_list`；第04章配置助手默认关闭旧重点窗口。先得到新片基线，再根据新片真实问题选窗口。
8. 超过15秒的新片应相应增大 `env.episode_length_s`，至少覆盖完整片长并留余量；否则训练可能总在跳完之前被时间上限截断。评测入口会按整段执行。

本教程能教你独立完成这个流程，但人工判定“哪只脚在何时真的支撑”仍然是数据整理的一部分，没有一条已验证的命令保证任何网络舞蹈都能自动变成完美机器人动作。
