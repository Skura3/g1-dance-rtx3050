## 1. 先认识五个东西

| 名称 | 你可以怎样理解 | 本项目中的东西 |
|---|---|---|
| 机器人模型 | 身体说明书：骨架、关节、质量、电机、碰撞外形 | G1 的 XML 和网格资源 |
| 仿真环境 | 带重力、地面和接触的虚拟实验室 | MuJoCo + MuJoCo Warp + mjlab |
| 参考动作 | 每个时刻希望身体处在哪里的“舞谱” | 50Hz 的 NPZ 文件 |
| 策略 policy | 看到当前身体状态和舞谱后，决定下一步关节指令的神经网络 | checkpoint 内的 policy |
| 训练 | 收集尝试结果并修改网络参数，使未来动作更好 | 反复采样、拟合世界模型、更新策略与 critic |

G1 有浮动的骨盆和本项目使用的 29 个受控关节。骨盆不是被固定在空中；身体能站住，是关节指令通过电机模型产生力矩，与重力和地面接触相互作用的结果。XML 能加载，只说明身体构建成功，不说明它已经会站立或跳舞。

`state` 是仿真里的完整状态；`observation` 是提供给策略的输入；`action` 是策略输出。这里策略输出归一化关节目标，底层控制器将其转换为电机作用。关节目标不是下一帧必须达到的位置，机器人可能因为惯性、接触或力矩限制跟不上。

## 2. 从视频到策略的完整路径

```text
MP4 像素视频
  ↓ 视频预处理：帧率、尺寸、编码、时间轴
GVHMR：检测人、估计关键点与人体姿态、估计世界坐标运动
  ↓ SMPL-X 人体参数 / 三维运动
GMR：按人体与机器人骨架对应关系做逆运动学重定向
  ↓ G1 根位置、根旋转、29 关节角（PKL）
格式转换 + 身体正运动学 + 速度 + 接触修正
  ↓ G1 参考动作 NPZ，50Hz
mjlab 物理环境 + SuperMimic 学习循环
  ↓ checkpoint：世界模型、策略、critic、优化器等
独立物理评测 → 原速观看 → 选择展示版 → 保存续训版
```

**视频重建不是强化学习。** GVHMR 在这里使用已训练好的视觉网络做推理，我们没有从头训练人体识别网络。GMR 是把人的姿态变成机器人的姿态；人体和 G1 身材不同，不能直接复制人体关节角。参考修正也不是训练策略。

**运动学播放不是机器人已学会。** 强制设置每一帧的位置可以让机器人“摆出动作”，但可能脚滑、穿地、悬空。策略回放必须让自由身体在物理仿真里靠关节控制完成动作。后文会同时播放这两种结果，正是为了看出差异。

## 3. 两篇本地论文分别做什么

### SuperMimic

本地文献 `CoRL2026_SuperMimic.pdf` 标题为 *SuperMimic: Scaling Humanoid Whole-Body Control with One Differentiable World Model*。作者来自 UC Berkeley。方法主线见 PDF 第 4–5 页、Fig.2、式 (1)–(3)；训练算法和参数见第 15–16 页 Algorithm A.1、Table A.5。可搜索的[论文原文](https://arxiv.org/abs/2610.28480)保留原文分页。

核心不是“每次播放完一整段再算一次对错”，而是三个阶段持续交替：

1. **在真实物理仿真中采样**。当前策略控制多个 G1，记录状态、实际执行的动作、下一状态、奖励、是否终止，以及仿真上下文。经验放入固定容量 replay buffer。新数据逐渐替换旧数据。这里“真实”指 MuJoCo 物理推进，仍然是仿真，不是真机。
2. **训练世界模型**。神经网络预测“在这个身体状态下，发出这个动作，接下来会怎样”。从缓存抽取连续的 8 步窗口，使用记录的动作逐步向前预测，再和仿真记录比较。多步监督有助于减少误差累积。根据实现，有些奖励/观测项通过正运动学解析计算，终止概率等由模型预测。
3. **通过世界模型训练策略**。暂时固定世界模型的权重，让策略在模型中“想象”短时间动作。对预测奖励反向传播，告诉策略哪些动作应增大或减小。critic 估计短窗口之后的长期收益，避免只顾眼前。下一轮继续收集真实仿真数据，修正模型和策略。

世界模型可以概括为 `下一状态 ≈ f(当前状态, 动作, 仿真上下文)`。策略的目标可以概括为“短时间内的折扣奖励 + 窗口末尾的未来价值”。实际式 (2) 还有存活权重：预测越可能已经失败，后面的收益权重越低。critic 的目标使用 TD-λ 返回；论文 λ=0.95。

这里要特别理解“固定权重”：策略更新时不修改世界模型参数，但**仍然允许梯度穿过模型对输入和动作求导**。把整个模型放进 `no_grad()` 会切断策略需要的梯度，是错误做法。

它属于**基于模型的强化学习（MBRL）**。不用 PPO 并不意味着不是强化学习：它仍根据动作造成的结果和任务奖励改进控制。相较把动力学当黑箱的 PPO，它借助可微世界模型做 BPTT（沿时间展开的反向传播）。梯度经过学到的模型，不要求 MuJoCo 本身可微。模型也可能预测错，所以必须不断用物理数据校正，不能只看想象奖励上涨。

论文原设置的想象时域为 32 步；我们为了 4GB 显存使用 16 步。50Hz 控制时，16 步约 0.32 秒，**不是只学舞蹈前 0.32 秒**：起点遍布整段，critic 估计更远的收益，多轮更新逐步形成完整控制。

论文研究的是大量动作共享一个世界模型；本项目聚焦一段 12 秒舞蹈。论文所用 H100 上的耗时不能换算为你的 3050 上的完成承诺。也不能把非官方复现等同作者原始实现。

### mjlab

本地文献 `2601.22074v2.pdf` 是 *mjlab: A Lightweight Framework for GPU-Accelerated Robot Learning*，2026-02-25 版本。它讲的是**训练基础设施**：用 MuJoCo Warp 在 GPU 上并行仿真，采用可组合的 manager 结构管理观测、奖励、事件、命令等，并保留原生 MuJoCo 数据访问。[论文原文](https://arxiv.org/abs/2601.22074)。

mjlab 不是“SuperMimic 算法的另一个名字”。同一仿真框架可以搭配不同算法。本项目用 mjlab 产生机器人与地面的物理交互，用 SuperMimic 的训练循环更新世界模型和策略。没有真机仍能完整完成这些步骤。

## 4. “训练一轮”为什么容易误解

- **仿真一步**：时间向前推进一个控制周期。50Hz 时约 0.02 秒模拟时间。
- **并行环境数**：同时有多少个机器人尝试。64 个环境的一次采样会产生约 64 条状态转移。它不是 64 个 Python 进程或 64 个可视窗口。
- **训练 iteration**：本实现日志主要按环境采样迭代计数，不等于整段舞蹈播放次数。
- **更新次数**：神经网络参数实际优化了多少次；由更新调度控制，与 iteration 不相等。
- **batch_size**：一次抽取多少条训练窗口/想象起点，不是视频分辨率、帧数或环境数。
- **episode**：机器人从一次初始化到终止/时间上限的一段经历；训练会随机从参考不同时间开始。
- **evaluation**：冻结某个检查点，从第 0 帧完整播放，专门测它表现怎样。

本次检查点自带公开预训练计数 291000。最后 452376 不是在你电脑上从零训练了 452376 步；沿最终继承链相对公开计数增加了 161376。早期试验有不同分支，不能把所有分支的步数简单串起来。

## 5. 什么错误该修，什么错误该允许学习

训练前必须修：NaN、损坏权重、错误关节顺序、单位/四元数顺序错、动作时间轴错、显存持续不足、模型无法执行。这些会使学习目标或程序本身失效。

可以在早期允许：摔倒、跟踪偏差、奖励波动、某个动作没做全。奖励和物理反馈就是让它逐渐改正这些问题。几百步的短测只能证明管线能采样、更新、保存；不能证明算法不行，更不应要求短测达到最终精度。

我们早期过度关注少量步数下的误差、把简单 PD / 瞬时动力学筛查当过强的门槛，这会推迟真正学习。后续改为固定主要配置持续训练、每约 4000 步评测，保留最佳与最新状态，观察多个点的趋势。筛查仍然帮助发现参考错误，但不能证明一个学习控制器一定无法完成。

为什么 MP4 不能直接作为控制指令？为什么会播放参考不等于学会？世界模型、策略和 critic 各负责什么？为什么要同时看真实仿真误差和训练损失？为什么本次是微调而不是随机初始化？
