## 1. 先分清三种“好”

1. **程序正常**：采样和更新持续进行，没有OOM/NaN，能保存检查点。
2. **控制正常**：自由身体在重力下能完成整段，无中途重置、扶持或提前终止。
3. **动作好看**：朝向、位置、手脚与节奏接近参考，困难片段没有明显变形。

第一条不保证第二条，第二条也不保证第三条。训练随机起点的平均回报高，可能只说明多数短段容易；必须从0帧完整测一次。

每4000步评测一次即可。不要每几十步开窗口判断“还没学会”。先看2–3个相邻评测点，再决定是否值得改动；若只是正常波动就继续。显存不足、NaN或动作文件错则应立即处理，不等待多次质量评测。

## 2. 报告里的数字怎么读

监督器将评测写到 `logs/train/你的run-name/evaluations/步数/nominal/report.json`，汇总到 `evaluations.jsonl`，最佳排名写到 `best_evaluation.json`。

| 字段/现象 | 代表什么 | 应怎么判断 |
|---|---|---|
| steps、simulated_seconds | 实际执行长度 | 本片616步、12.32秒；不是进程运行了多久 |
| failed=false | 没有触发失败终止 | 还需检查长度，不能只看false |
| timeout=true | 本评测到动作结束触发时限 | 与616步全长同时出现是正常结束，不是Python超时崩溃 |
| norm_return | 把累计奖励归一化的得分 | 同参考、同奖励设置才适合比较，越高通常越好 |
| root_error_mean/max_m | 根位置距参考的绝对距离 | 米；看是否整体漂移或某个瞬间跑偏 |
| joint_rmse_rad | 全时段、所有关节的均方根误差 | 弧度；看总体姿态跟踪 |
| arms_joint_rmse_rad | 肩、肘、腕关节误差 | 避免手臂被全身平均掩盖 |
| worst_2s_joint_rmse_rad | 所有连续2秒窗口中的最差关节RMSE | 找到局部难段；本片窗口100采样 |
| tilt_mean/max_deg | 实际与参考根部重力方向的角度差 | 不是机器人相对竖直站姿的绝对倾斜 |
| yaw_error_mean/max_abs_deg | 包裹到±180°后的朝向误差 | 看转身和原地旋转，不能事后转动参考消除误差 |
| aligned_body_error | 去掉部分平移/偏航后的身体形状误差 | 不能单独用于判断全局位置/朝向正确 |
| wm nse1 / nse8 | 世界模型短期预测误差 | 趋势下降有益，但不等于真实策略跟踪一定改善 |
| imag_ret / imag_survival | 世界模型里想象的收益/存活 | 如涨而物理表现差，要警惕策略利用模型误差 |

弧度转角度约乘57.3。0.2rad约11.46°，是汇总RMSE，不是每个关节始终误差小于11.46°；个别时刻可能更大。

单目重建、机器人比例和接触修正本身已有误差。这些指标比较的是**策略与G1参考NPZ**，不是与原视频真人的真实3D运动比较。即使策略误差为0，也不能证明重建忠实真人。

## 3. 本次最终展示为什么选429526

下表直接来自归档 `display/evaluation_report.json`：

| 指标 | 429526展示版 | 严格工程目标 |
|---|---:|---:|
| 全片长度/是否失败 | 616步，failed=false | 全片、无中途重置 |
| 全身关节RMSE | 0.1640rad（约9.40°） | ≤0.20rad |
| 手臂RMSE | 0.1803rad | ≤0.25rad |
| 最差连续2秒RMSE | 0.2313rad，起点7.48秒 | ≤0.30rad |
| 平均/峰值根位置误差 | 6.51 / 15.45cm | ≤10 / 25cm |
| 平均/峰值偏航误差 | 5.10 / 39.04° | ≤5 / 20° |
| 平均/峰值倾斜误差 | 5.35 / 17.06° | ≤5 / 15° |

它完成动作、关节和位置指标较好，但偏航与倾斜没有全部通过严格阈值。你在原速观看后认可观感，因此选择它展示并结束本轮。**这是人工接受有限误差，不是所有指标达标，也没有完成最终三种初态扰动确认。**

严格目标是工程愿望，**没有经过证明的“理论可实现最低阈值”**。零误差受视频不确定性、形态差异、动力学与学习能力限制，不能承诺。峰值39°的朝向偏差在对应瞬间可能看得出来，尤其手撑/大幅俯身时yaw表示也更敏感；应该原速和慢放定位看，而不是用全片平均5°保证肉眼无差。

最终保存452376步只是最后训练状态，未另做全片独立评测，不能因为步数更大就断言更好。训练不单调：以后继续也要保留这个展示版。

## 5. 看自己新训练的结果

训练活跃时不要直接复制仍可能变化的 `ckpt_latest.pt` 做对比。优先使用已经固定的 `eval_XXXXXXXXX.pt`，或先请求保存退出再使用最新权重。先看 `best_evaluation.json` 选择检查点，并把这一份复制到单独的展示目录后再评测。

以下假设你已安全停下 `tutorial_dance_01_long`，并且它至少产生过一次可用最佳评测。若没有 `ckpt_best_evaluated.pt`，用已保存的 `ckpt_latest.pt` 做诊断，不能声称它是最佳。

```bash
mkdir -p outputs/tutorial_runs/tutorial_dance_01/display
cp -n logs/train/tutorial_dance_01_long/ckpt_best_evaluated.pt outputs/tutorial_runs/tutorial_dance_01/display/checkpoint.pt
MUJOCO_GL=egl OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
envs/training/.venv/bin/python tools/record_nju_rollout.py \
  --checkpoint outputs/tutorial_runs/tutorial_dance_01/display/checkpoint.pt \
  --motions data/preview/reference_full_contact.npz \
  --output outputs/tutorial_runs/tutorial_dance_01/display/rollout
```

`cp -n` 不覆盖已存在文件：若想展示另一个检查点，请新建display目录，不要以为重复执行就替换了。完成后查看 `report.json`。若提前失败，先看产生的policy MP4定位；不能把失败轨迹循环播放当成全段成功。

对完整无失败轨迹，本教程提供独立通用对照入口：

```bash

envs/training/.venv/bin/python -B docs/tutorial/scripts/view_comparison.py \
  --report outputs/tutorial_runs/tutorial_dance_01/display/rollout/report.json \

  --model outputs/tutorial_runs/tutorial_dance_01/display/rollout/g1_scene.mjb \
```

它复用已验证播放器的墙钟逻辑，改为显式指定模型和按报告验证帧数，支持不同片长。原429526展示播放器没有被改动。教程编写时对这个新入口做了接口/数值/结构核对，没有额外打开GUI或重新训练来验证一个新动作。

继续训练时也可播放**已经生成**的轨迹，负担较小；实时策略推理加物理仿真再加训练曾明显低于原速。因此“画面很慢”先检查播放时间是否实时，不要直接改动作FPS或奖励。`--no-render` 的评测省资源但不会生成场景MJB和视频；用于交互对照时要有同一机器人模型的MJB。

## 6. 什么情况停止，什么情况继续

连续监督训练的停止条件：

- 两个不同检查点连续满足工程阈值，再通过3个初态扰动种子：保存接受版，等待视觉确认。
- 用户请求：到安全边界保存最新状态退出。
- 非有限数、严重运行错误、磁盘过低等资源故障：结束或报错，依靠最后成功的原子检查点恢复；不保证故障时内存状态能存盘。
- 独立看护触发温度或步数停滞条件：固定最佳、请求保存，必要时结束进程，记录是否真正保存成功。

“本次评测仍失败”“误差比上次稍大”“已观察3个点”“4小时奖励没增长”都**不是**现有监督器自动终止训练的条件。`review_after_evaluations` 只标记观察窗口完成，不自动调参或停止。

何时值得人工调整：若多个间隔足够长的评测点中完整率、误差和观感都不再进步，先查是否同一个困难段、参考接触错、漂移、世界模型预测恶化或采样偏置。一次只改一个主要因素，继续使用已保存的网络/优化器，新目录记录分支。比较每小时质量改善，别只比较GPU占用或某一次reward。

## 7. 安全结束自己这次训练

只对使用 `--until-targets` 的本地微调入口，另开终端执行：

```bash
cd "$G1_PROJECT_ROOT"
touch logs/train/tutorial_dance_01_long/STOP
```

它不是立即杀进程，而是请求在安全边界保存退出；如果正在评测，可能需要等评测结束或超时。然后查看：

```bash
cat logs/train/tutorial_dance_01_long/status.json
cat logs/train/tutorial_dance_01_long/run_report.json
ls -lh logs/train/tutorial_dance_01_long/ckpt_latest.pt
```

确认 `stopped_by_request`、报告 `ok=true`、最新权重存在，再关终端。不要默认关闭窗口或 `kill -9` 可以保存最后状态。原子保存会保护已有检查点，但不能挽救断电时未写出的数据。

保存新实验的成果时，将这几类放到一个新归档目录：人工认可展示权重与对应评测/轨迹、最新完整检查点、实际config、acceptance/supervision、参考NPZ、源码版本和哈希。展示版和最新续训版分开，不要用“最新”覆盖“最好”。

如果已经完成本章第5节的独立display评测，并决定接受它，可以在训练正常停止后运行以下归档示例。它只用于你的新实验，不碰429526/452376归档：

```bash
python3 - <<'PY'
from pathlib import Path
from datetime import datetime
import hashlib, json, shutil
root = Path.cwd().resolve()
run = root/'logs/train/tutorial_dance_01_long'
experiment = root/'outputs/tutorial_runs/tutorial_dance_01'
display = experiment/'display'
status = json.loads((run/'status.json').read_text())
report = json.loads((run/'run_report.json').read_text())
assert status['status'] in ('stopped_by_request','targets_met_video_review_pending')
assert report.get('ok') is True, '先确认正常保存退出'
eval_report = json.loads((display/'rollout/report.json').read_text())
hash_file = lambda p: hashlib.sha256(p.read_bytes()).hexdigest()
assert hash_file(display/'checkpoint.pt') == eval_report['checkpoint_sha256']
assert eval_report['clips'][0]['failed'] is False, '先检查完整物理评测'
session = json.loads((experiment/'session.json').read_text())
motion = root/session['motion']
needed = sum(p.stat().st_size for p in display.rglob('*') if p.is_file())
needed += (run/'ckpt_latest.pt').stat().st_size + motion.stat().st_size
assert shutil.disk_usage(root).free > needed + 2*1024**3, '先给归档留够空间'
dest = root/'outputs/my_archives'/datetime.now().strftime('%Y%m%d_%H%M%S')
dest.mkdir(parents=True, exist_ok=False)
shutil.copytree(display, dest/'display')
shutil.copyfile(run/'ckpt_latest.pt', dest/'checkpoint_final.pt')
shutil.copyfile(motion, dest/'reference_motion.npz')
for name in ('config.json','supervision.json','criteria_snapshot.json','run_report.json','status.json','resume_validation.json','best_evaluation.json'):
    source = run/name
    if source.is_file(): shutil.copyfile(source, dest/name)
shutil.copyfile(experiment/'finetune.json', dest/'finetune.json')
shutil.copyfile(root/'configs/upstream_sources.json', dest/'upstream_sources.json')
eval_report['checkpoint'] = str(dest/'display/checkpoint.pt')
for clip in eval_report['clips']:
    clip['states'] = str(dest/'display/rollout'/Path(clip['states']).name)
(dest/'display/rollout/report.json').write_text(json.dumps(eval_report,indent=2))
manifest = {'display_iteration':eval_report['checkpoint_iteration'],
            'final_iteration':report['final_iteration'],
            'display_sha256':hash_file(dest/'display/checkpoint.pt'),
            'final_sha256':hash_file(dest/'checkpoint_final.pt'),
            'reference_sha256':hash_file(dest/'reference_motion.npz'),
            'note':'User-selected display; latest state retained separately; requires project source and environment to resume.'}
(dest/'manifest.json').write_text(json.dumps(manifest,indent=2))
print(dest)
PY
```

此示例复制场景MJB与物理轨迹，改写新副本内的绝对路径。源码和环境仍按第02章另行保留。续训用新归档的 `checkpoint_final.pt`、`finetune.json`；复制supervision到新的实验目录，并删除其中固定 `first_evaluation_iteration` 后使用，新run-name必不可少。

它恢复世界模型、策略、critic、三个优化器及其动量、采样统计和计数。启动时生成 `resume_validation.json` 检查加载内容。实际batch仍1024，首个评测安排在456376，再每4000步一次。

**没有保存**整个回放缓存、现场仿真状态和随机数生成器状态。缓存重建、64步预热，所以是继续学习，不是原进程逐位精确续跑。旧429526展示副本保持不变。

如要再次从此后的最新checkpoint继续，不要继续沿用固定首评456376：如果起始步数已经超过它，监督器会拒绝。在新的supervision副本中删除 `first_evaluation_iteration`，就会从起始步数再加4000；不要直接修改归档原件。

手动命令不自动停止壁纸、不阻止休眠、不重新绑定看护。夜间运行看第07章；不要重启旧 `supermimic-g1-strict.service`，它仍指向335263阶段的历史恢复点。

## 9. 用什么判断自己真的复刻成功

不是得到同名checkpoint，也不是必须恰好训练到429526。你应能说明参考来自哪个视频、有没有改时间轴、实际加载哪个源码和权重、是否从0帧完整物理执行、关键指标多少、观感是否接受，并保留对应文件。新训练的数值和最佳步数不同很正常；证据和流程可重复比一个完全相同的数字更重要。
