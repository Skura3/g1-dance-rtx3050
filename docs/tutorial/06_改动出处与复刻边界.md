> **GitHub读者先看 [公开版复刻入口](../PUBLIC_REPRODUCTION.md)**：设置G1_PROJECT_ROOT、恢复上游源码、下载Release。原机/home/djs/supermimic、历史outputs/logs和systemd实例未原样分发；已有成果的播放/续训请使用公开版入口的命令。


[目录](README.md) · 上一章：[评估与续训](05_评估播放与续训.md) · 下一章：[操作清单与排错](07_操作清单与排错.md)

## 1. 源头必须分清

- **论文作者**提出SuperMimic：同一学习循环中更新可微世界模型、通过模型BPTT更新策略、训练critic，利用共享动力学学习大量动作。
- **CuboiLeo/SuperMimic-Reproduced**是独立非官方复现，给出可运行训练器、模型、mjlab连接、奖励和数据处理；也作出了论文未完全规定的实现选择。
- **NJU-R-L-Group-Embodied-Lab/SuperMimic-Repro-Sim2Real**在该复现基础上增加经验、检查点和真机相关改进。我们后期实际训练用这份源码。
- **本地项目**将视频处理、G1格式、4GB适配、检查点迁移、单舞蹈微调、低频评测、看护和展示整合起来。

两个GitHub仓库都不能冒称论文作者的官方原始训练代码。本地结果也不是论文所有实验的复现：只有一段自己的舞蹈，没有整个BONES-SEED基准、没有多GPU、没有真机迁移。

## 2. 论文关键机制，我们保留与改变了什么

| 项目 | 论文或复现基础 | 本地实际 |
|---|---|---|
| 物理采样→世界模型→策略/critic交替 | Fig.2 / Algorithm A.1 | 保留；不是换成PPO |
| 世界模型自回归监督 | k=8 | 保留8步 |
| 想象策略梯度 | BPTT，冻结模型权重，保留输入梯度 | 保留 |
| 终止与未来收益 | 存活权重+critic bootstrap，λ=0.95 | 沿用训练器 |
| 经验回放与困难起点采样 | 不断更新缓存；低回报时间段多练 | 保留；另加本片重点窗口 |
| 想象时域 | H=32 | H=16，降低显存与计算量 |
| 并行环境 | 4096/GPU | 64 |
| WM每更新批次数 | 10×2048窗口 | 2批；每批32→512→1024 |
| 策略batch | 4096 | 32→512→1024 |
| 缓存容量 | 1000步/环境 | 512步/环境 |
| 更新比率 | 0.4 | 0.4 |
| 初始权重 | 论文大规模训练研究 | NJU公开291000检查点微调 |
| 学习率 | 论文2e-4并余弦衰减 | 恒定2e-5微调，保留优化器状态 |
| 数据 | 大量重定向动作库 | 一段616帧参考 |
| 观测 | 原论文可部署本体感知路线 | 加9维anchor；仅仿真 |

所以应称“基于SuperMimic方法的低显存单舞蹈微调”，而非“完全使用论文相同参数从零复现”。完整预训练网络形状沿用checkpoint；早期小网络只用于环境/性能实验，没有用于最终展示微调。

## 3. 从NJU获得并实际使用的内容

| 内容 | 是否使用 | 出处与具体用途 |
|---|---|---|
| e13i_0291000公开检查点 | 是 | 作为已有动作控制/世界模型能力的起点，而非让4GB从随机权重学习全部技能 |
| NJU单舞蹈微调经验 | 是 | 采用低学习率、保留世界模型/策略/critic/优化器，集中优化自己的动作 |
| anchor_obs相对锚点反馈 | 是，但**不是NJU独创** | CuboiLeo基础仓库中已经有；NJU METHOD总结其效果，我们通过NJU路径使用 |
| tilt hinge附加倾斜惩罚 | 是 | NJU提供选项；本地设weight=-24、knee=0.17rad，仿真与想象保持一致 |
| fail_reset重点起点采样 | 是 | NJU提供机制；本地把25%起点放在自己的质量问题前2秒，列表来自本片 |
| 从0帧整段物理评测 | 是 | 借鉴完整无中途重置的评测纪律；本地另加绝对朝向、局部2秒等指标 |
| 不因简单筛查差就否定策略 | 是，作为经验 | NJU实机记录中显示某些“看起来严格”的筛查与实际效果未必一致；我们据此重视真实策略回放证据 |
| 真机日志回灌、真实失败状态reset | 否 | 我们没有真机日志 |
| 腰部耦合、IMU饱和、动作延迟、推力DR等 | 最终没有启用 | 仓库有代码不等于我们的实验使用；最终配置中相应开关关闭/概率0 |
| 实机SDK、通信、安全吊装、遥控流程 | 否 | 用户只要求仿真 |
| NJU另一个重定向候选 | 尝试过但没有采用 | 发现自碰撞等问题，保留本地contact参考，不覆盖好版本 |

本地 `fail_reset` 文件名含“failure”，但标注的是4.2秒踢腿、7.8秒手撑、9.32秒倾斜与11.86秒朝向等**质量问题**，不代表每处都发生了摔倒终止。NJU的真实失败状态回灌是另外一种机制，不能混为一谈。

NJU文档中的实机成功是对其特定机器人、动作和检查点的报告，不自动保证我们的仿真策略能迁移。特别是我们开启anchor后依赖仿真提供的全局状态。

## 4. 本地主要工程改动与对应文件

### A. 视觉阶段：使4GB能运行

- [`tools/patch_gvhmr_lowmem.py`](../../tools/patch_gvhmr_lowmem.py)：将整段图像留CPU，单批传GPU；预处理batch1；可选CUDA FP16；权重先加载到CPU；默认关闭翻转增强，避免双倍推理；可选KNN延迟导入。
- [`tools/run_gvhmr.py`](../../tools/run_gvhmr.py)：五阶段独立进程、文件缓存与来源核对、必要组件配置、SimpleVO；避免通用demo一次加载训练数据集/渲染器。
- 两种精度在历史抽样比较中关键点最大差约0.096像素，HMR2特征最低余弦相似度约0.999998；这只是抽样数值一致性证据，不是所有新视频FP16永无差异的保证。

上游原文件备份在 `outputs/upstream_backups/`，差异记录 `configs/upstream_changes.patch`。补丁有版本守卫，匹配不到原语句就拒绝修改；不要手动删除检查然后套到新版本。

### B. 动作阶段：把姿态变成可审计的参考

- [`tools/retarget_g1.py`](../../tools/retarget_g1.py)：CPU分批SMPL-X、逐帧GMR、显式元数据，保留完整视频。
- [`tools/convert_motion.py`](../../tools/convert_motion.py)：关节命名重排、xyzw→wxyz、固定地面对齐、50Hz采样、FK和速度；输出校验与来源。
- [`tools/repair_motion.py`](../../tools/repair_motion.py)、[`tools/refine_contacts.py`](../../tools/refine_contacts.py)：稀疏高度锚点、肩部跳变、自碰撞候选修正、手脚接触约束。保留原版本和新候选。
- [`tools/audit_motion.py`](../../tools/audit_motion.py)、[`tools/audit_dynamics.py`](../../tools/audit_dynamics.py)：质量/动力学筛查。动力学工具修过执行器排序与接触力臂计算，仍有近似假设，不作为策略可行性定理。

### C. 训练阶段：省资源但保留方法

- 两套Python环境；本地CUDA12 Torch/Warp wheel；沿用工作驱动。CUDA Graphs由兼容性检查禁用，未强开。
- [`tools/fast_g1_fk.py`](../../tools/fast_g1_fk.py)：按机器人树深度批量计算同层身体，减少小GPU操作。核对姿态、速度、前向与输入梯度后使用；不删网络层、不改物理关节限制。
- [`tools/extend_anchor_checkpoint.py`](../../tools/extend_anchor_checkpoint.py)：680→689输入迁移与优化器动量迁移，零列保持初始函数。
- [`tools/finetune_nju.py`](../../tools/finetune_nju.py)：CPU加载checkpoint、只迁移需要的张量；单舞蹈路径覆盖；固定微调学习率；在线诊断batch≤64；数值检查、原子存盘、日志轮转、同库恢复核对。
- `tools/train_3050.py` 的配置覆盖器允许可选tuple变为None，避免从大库配置迁移时出错。
- NJU固定提交**自身已经包含** `lr_at/apply_lr/effective_lrs` 和恢复后立即应用/报告实际学习率的逻辑；这是我们核对并使用的上游能力，不能算成本地新增。CuboiLeo训练循环的本地补丁主要限制在线诊断批量。迁移新机器时保留实际源码或归档 `source_snapshot/`，不能只凭一份早期patch推断所有版本状态。

历史同工作量短基准：分层FK预计每迭代1.063→0.682秒，约1.56倍；这是短基准，不保证长训每个阶段都是这个速度。最终完整网络batch1024与早期小网络性能实验的条件也不同，不能直接横向比较。

### D. 训练管理与展示

- [`tools/training_supervisor.py`](../../tools/training_supervisor.py)：每4000步完整评测、1000步恢复存盘、连续成功+扰动确认、磁盘检查、保留最佳/最新，允许早期失败继续学习。
- [`tools/record_nju_rollout.py`](../../tools/record_nju_rollout.py)：真正自由身体物理执行，保存终止状态、不隐藏失败；额外报告偏航、绝对根位置、手臂和最差2秒误差。
- [`tools/training_watchdog.py`](../../tools/training_watchdog.py)：CPU独立看护，绑定服务InvocationID，>100°C或>4小时无步数进展时请求保存停止并记原因。
- [`tools/view_best_replay.py`](../../tools/view_best_replay.py)：把已验证物理轨迹与无策略参考放在同一原生窗口，按墙钟原速展示；没有改训练策略来“播放得更快”。
- 最终将人工认可429526与最后452376独立归档，验证167个张量均有限，保留三个优化器及采样器统计。

## 5. 这次教程新增了什么

只新增文档、环境清单、独立配置助手 `docs/tutorial/scripts/prepare_run.py`、通用参考/策略轨迹播放器 `view_comparison.py`，以及教程自检记录；更新项目README入口。配置助手默认不启用旧片重点窗口、拒绝重复实验名。播放器接受显式MJB和动态帧数，解决原展示工具专门固定616帧的限制。

没有为写教程启动训练、改奖励、修改最终checkpoint、重建现有环境或重新处理原视频。两个新助手是教程工具，不应算作之前训练成功的原因。

## 6. 仍然存在的边界

单目视频不提供唯一真实3D答案；人体与G1比例不同；手撑/腾空/遮挡段难；接触修正会改变动作；严格朝向与倾斜目标未全部通过；同片扰动鲁棒性最终未完成；原速显示的是已验证轨迹而非实时策略推理；续训没有现场缓存与RNG逐位恢复。

这些不是“做不了任何事”的结论。它们告诉你实验结果证明了什么：**在这台3050 4GB上，一段自己的视频可以经过整理与预训练微调，得到被你认可的G1仿真舞蹈展示。** 没有证明任意视频、任意扰动或真机部署都能直接成功。
