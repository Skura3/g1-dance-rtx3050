## 1. 第一次独立操作的路线卡

不要一次复制所有章节的命令。每次只推进到下一个检查点。下面的时间是操作顺序，不是速度承诺。

| 顺序 | 做什么 | 完成后你应拿到什么 | 若失败先查 |
|---|---|---|---|
| 1 | 检查系统与空间 | nvidia-smi可用、磁盘有余量 | 驱动、磁盘，不先装十几个包 |
| 2 | 两个环境检查 | motion模块、训练Torch/Warp能工作 | Python路径、版本、wheel格式 |
| 3 | 素材审计 | neutral SMPL-X、4视觉权重、e13i权重 | 名称、目录层级、文件内容/hash |
| 4 | 处理视频 | 可播放的H.264、帧数/FPS正确 | 编码、视频方向、人物是否完整 |
| 5 | GVHMR五阶段 | hmr4d_results.pt，370帧 | 上一阶段缓存、OOM、人物轨迹 |
| 6 | GMR重定向 | 带显式元数据的PKL | 模型路径、关节对应、SMPL-X批量 |
| 7 | 转50Hz和修正 | 616帧NPZ、审核报告、接触标注 | 四元数、顺序、地面、人工时间 |
| 8 | G1站立/动作读取 | 站立与GPU FK报告 | 模型、执行器、环境，不看学习reward |
| 9 | 公开模型基线 | 全片物理report/轨迹 | 是真的物理推理还是摆姿态 |
| 10 | 配置和anchor迁移 | 独立run目录、689维权重 | 不把小网络/旧680维混用 |
| 11 | 600步工程短测 | 有更新、有checkpoint、数值有限 | 不因早期动作差否定长训 |
| 12 | 长期连续训练 | 每4000步完整评测，持续保存 | 看数个点趋势，不频繁改方法 |
| 13 | 原速对照观看 | 参考和实际策略结果 | 显示是否按墙钟1倍速 |
| 14 | 人工/自动停止与归档 | 展示版+最终续训版+配置/参考/报告 | 最后状态不一定最好，分别保存 |

如果第03章重建版暂时和已有参考略有不同，可以先用已有 `data/preview/reference_full_contact.npz` 学会训练流程；这是“复刻训练”，不能宣称重新完成了自己的视觉处理。之后再接上你的新候选比较。

## 2. 夜间运行：创建一个新的服务，不重启历史服务

这部分是可选的进阶操作。先完成前台600步验证，并确认没有另一个训练进程。**以下命令只有你执行时才启动训练；写教程时没有运行。**

这里以从 `tutorial_dance_01_warmup` 继续到新的 `tutorial_dance_01_night` 为例。若你要从最终452376续训，把下面Python里的checkpoint/config/supervision三个路径换为第05章归档路径，并换一个新名字。

先在桌面正常退出动态壁纸程序，保留散热空间、插电。锁屏可以，合盖/注销/休眠可能终止或暂停作业。程序用sleep inhibitor阻止普通休眠；不修改BIOS/驱动/温度保护，也不设置自动开机训练。

### 2.1 生成服务文件（尚不启动）

```bash
cd "$G1_PROJECT_ROOT"
python3 - <<'PY'
from pathlib import Path
root = Path.cwd().resolve()
name = 'tutorial_dance_01_night'
unit = 'supermimic-' + name + '.service'
run = root / 'logs/train' / name
checkpoint = root / 'logs/train/tutorial_dance_01_warmup/ckpt_latest.pt'
config = root / 'outputs/tutorial_runs/tutorial_dance_01/finetune.json'
supervision = root / 'outputs/tutorial_runs/tutorial_dance_01/supervision.json'
unit_file = Path.home() / '.config/systemd/user' / unit
assert ' ' not in str(root), '此教学服务模板要求项目路径没有空格'
assert not run.exists() and not unit_file.exists(), '名字已使用，请换一个新名字'
assert all(p.is_file() for p in (checkpoint, config, supervision)), '缺少输入文件'
run.mkdir(parents=True)
unit_file.parent.mkdir(parents=True, exist_ok=True)
unit_file.write_text(f'''[Unit]
Description=G1 tutorial supervised training

[Service]
Type=simple
WorkingDirectory={root}
Environment=PYTHONUNBUFFERED=1
Environment=MUJOCO_GL=egl
Environment=G1_SUPERMIMIC_SOURCE=nju
Environment=OMP_NUM_THREADS=1
Environment=MKL_NUM_THREADS=1
Environment=OPENBLAS_NUM_THREADS=1
ExecStart=/usr/bin/systemd-inhibit --what=sleep --mode=block --who=SuperMimic --why=G1-tutorial-training {root}/envs/training/.venv/bin/python -B {root}/tools/finetune_nju.py --config {config} --checkpoint {checkpoint} --run-name {name} --keep-sampler --until-targets --supervision {supervision}
Restart=no
KillMode=control-group
KillSignal=SIGTERM
TimeoutStopSec=900
StandardOutput=append:{run}/console.log
StandardError=inherit
''')
print(unit_file)
PY
systemctl --user daemon-reload
```

检查 `~/.config/systemd/user/supermimic-tutorial_dance_01_night.service` 内容。如果已经在第04章启动前台long训练，请先安全停止它，之后把这里的checkpoint改为那个long最新权重；不要浪费已学习部分重新从warmup开始。

### 2.2 启动并确认有进展

```bash
systemctl --user start supermimic-tutorial_dance_01_night.service
systemctl --user status supermimic-tutorial_dance_01_night.service --no-pager
tail -n 20 logs/train/tutorial_dance_01_night/console.log
```

等待初始化，确认 `status.json` 的iteration开始增长。如果服务因 `systemd-inhibit` 权限/会话问题失败，应先解决此报错，不要以为服务start成功就已经训练。不要重复点击启动多个名字。

### 2.3 绑定独立看护

看护必须绑定**本次启动的InvocationID**，不能复制旧服务配置的ID。下面自动读取本次服务和GPU UUID，并生成新的看护配置。它没有加载模型，不消耗训练GPU显存。

```bash
python3 - <<'PY'
from pathlib import Path
import json, subprocess
root = Path.cwd().resolve()
name = 'tutorial_dance_01_night'
service = 'supermimic-' + name + '.service'
watch_service = 'supermimic-' + name + '-watchdog.service'
raw = subprocess.check_output(['systemctl','--user','show',service,'-p','ActiveState','-p','InvocationID'],text=True)
state = dict(line.split('=',1) for line in raw.splitlines() if '=' in line)
assert state.get('ActiveState') == 'active' and state.get('InvocationID'), '训练服务尚未正常运行'
uuids = subprocess.check_output(['nvidia-smi','--query-gpu=uuid','--format=csv,noheader'],text=True).strip().splitlines()
assert len(uuids) == 1, '此教学模板针对单GPU；多GPU请明确选择训练GPU'
out = root / 'outputs/training_watchdog' / name
assert not out.exists(), '旧看护目录不能复用，请换新名字'
out.mkdir(parents=True)
cfg = json.loads((root/'configs/g1_3050_watchdog.json').read_text())
cfg.update(training_service=service, invocation_id=state['InvocationID'],
           run_dir=str(root/'logs/train'/name), output_dir=str(out), gpu_uuid=uuids[0],
           wallpaper_record=str(out/'wallpaper_record.json'),
           best_sources={'current_run':str(root/'logs/train'/name)})
(out/'wallpaper_record.json').write_text(json.dumps({'managed_by_tutorial':False}))
config = out/'config.json'
config.write_text(json.dumps(cfg,indent=2))
unit_file = Path.home()/'.config/systemd/user'/watch_service
assert not unit_file.exists(), '看护服务名已存在'
unit_file.write_text(f'''[Unit]
Description=Independent G1 tutorial training watchdog

[Service]
Type=simple
WorkingDirectory={root}
ExecStart=/usr/bin/python3 -B {root}/tools/training_watchdog.py --config {config}
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=inherit
''')
print(unit_file)
PY
systemctl --user daemon-reload
systemctl --user start supermimic-tutorial_dance_01_night-watchdog.service
systemctl --user status supermimic-tutorial_dance_01_night-watchdog.service --no-pager
cat outputs/training_watchdog/tutorial_dance_01_night/status.json
```

确认看护status为`watching`且温度可读，再离开。这里没有自动恢复壁纸的动作；训练结束后由你重新打开壁纸应用。历史服务的恢复脚本/旧记录不复用。

看护每10秒检查：GPU温度**严格超过100°C**，或iteration**严格超过4小时没有增长**。不是运行4小时就停，也不是reward4小时没变就停。100°C来自你之前指定的保护条件，不是建议运行温度；实际散热不好应提前人工暂停。

触发时先固定已有最佳与最近权重，写incident，创建STOP请求保存；过温给15秒、停滞给60秒，然后必要时停止服务，再必要时强制终止。强制终止不能保证刚才内存中的进度已保存，报告会记录这一点。第一次完整评测前可能还没有最佳版，但周期/latest检查点仍用于恢复。

看护只会对匹配InvocationID的服务操作。训练服务重新启动后ID改变，旧看护会退出；必须新建/重新绑定一份看护，不能认为旧看护永久有效。

## 3. 常见报错与处理顺序

| 现象 | 常见原因 | 先做什么 |
|---|---|---|
| No such file or directory | 工作目录错、少一层目录、名字不同 | `pwd`、`ls`核对；相对路径从项目根算 |
| ModuleNotFoundError | 用错Python或依赖缺失 | 看命令开头是motion还是training解释器 |
| 需要Python3.12 | 用motion环境跑训练 | 改用envs/training/.venv/bin/python |
| CUDA unavailable | 驱动/环境/CPU版Torch问题 | nvidia-smi、指定环境的check_training |
| Warp CUDA驱动不兼容 | 误装普通CUDA13版本 | 核对1.18.0+cu12 wheel；不要盲目换系统驱动 |
| CUDA out of memory | 大batch、两个GPU任务、桌面/壁纸占用 | 正常关闭无关GPU任务；视觉batch1；训练从小batch重新恢复 |
| FP16 dtype错误 | 模型与输入精度不一致或未应用补丁 | 固定版本重跑幂等补丁；新缓存目录 |
| Cache/provenance不一致 | 视频/精度变了却复用旧缓存 | 开新输出目录，不绕过保护 |
| SMPL-X找不到 | 外层zip没解开或模型类型错 | 核对body_models/smplx/SMPLX_NEUTRAL.npz |
| KNN/C++扩展不存在 | 使用了本路线不支持的PyTorch3D功能 | 回到本地精简入口，不运行通用渲染demo |
| checkpoint size mismatch | 小网络与大网络不匹配、680/689混用 | 用正确原配置；仅未扩展模型做anchor迁移 |
| sampler形状不匹配 | 换片却沿用旧采样统计 | 首次新片不加keep-sampler；同片后续才加 |
| 文件已存在/拒绝覆盖 | 复用了实验名字 | 新run-name，不删除好检查点强行继续 |
| No motion data | 配置仍指空pilot目录 | 明确设置npz_dir和clips，不只移动一个任意文件 |
| 机器人悬空/穿地 | 零点错、根高度漂移、接触不对 | 回看视频支撑时刻，检查参考，不先调reward |
| 早期摔倒 | 控制还没学好，也可能参考困难 | 先确定无结构/数值问题，再持续训练看多个点 |
| loss低但动作差 | 模型误差/奖励漏洞/采样覆盖或参考问题 | 比较真实完整回放、困难段与想象指标 |
| 界面动作慢 | 在线物理和训练争GPU、显示帧率不足 | 播已记录物理轨迹，保持墙钟1x，不改动作时间 |
| GLFW/DISPLAY错误 | 不在桌面会话或缺图形后端 | 桌面终端运行viewer；无窗口评测使用egl |
| 看护说无进展 | 迭代真正停滞或读不到匹配日志 | 查训练服务、日志、InvocationID；不是奖励阈值 |
| 磁盘不足 | 多份大checkpoint/缓存/环境 | 先备份归档；清理明确不要的实验副本，勿删最终成果 |
| “全片通过”但不好看 | 只检查了生存，未检查精度 | 看yaw/root/arms/worst2s和原速视频 |

报错时保留最后约30行终端文本、执行的完整命令、Python路径和相关JSON。不要反复运行下载十次；单个下载两次失败后转手动，按第02章链接与目标路径处理。

## 4. 怎么写实验记录，避免自己把自己绕晕

每次新实验写几行就够：

```text
实验名：tutorial_dance_02
参考：某NPZ，帧数/FPS/哈希
起点：某checkpoint，iteration是多少
这次只改什么：例如两种batch都从32改到512
保持什么：相同参考、网络、奖励、H、学习率、评测协议
结果：三个评测点的完整率、root/yaw/tilt/joint、每小时进步
决定：继续、保留为候选、恢复旧版或人工结束
```

如果一次改了学习率、anchor和奖励，就不能把改善全部归功于其中一个。若比较不同参考，误差更小可能只是目标变简单了；记录修改后的NPZ哈希。

## 5. 最后记住的十句话

1. 先确认自己在哪个目录、用哪个Python。
2. MP4→人体→机器人参考→策略，四个阶段不要混为一谈。
3. 显示参考动作不证明机器人能在物理中完成。
4. 原始视频、重建和失败候选都要保留，修改产物另存。
5. 接触时间属于具体视频，不可照搬到新片。
6. 几百步短测只判断管线健康，不要求已学会舞蹈。
7. 完整评测看多个点，平均误差和最差片段都要看。
8. 最新权重不一定最好，展示版与续训版分开。
9. 续训必须从已有checkpoint加载，不能只把计数手动写大。
10. 论文、上游经验和本机证据分清，有限误差可以接受，但要说清接受了什么。
